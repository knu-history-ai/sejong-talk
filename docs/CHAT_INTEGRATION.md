# W03-11 글 대화 연결 (#46)

글 대화 화면과 #48의 Ollama·Qwen 호출 코드를 연결했다. PR #51 병합 후 팀 통합 시험은 `dev`에서 진행한다. 병합 전 코드 확인에는 `codex/46-ai-integration`을 사용한다. 실제 Qwen 답변·출처 표시와 응답 시간은 모델이 설치된 유진 PC에서 확인한다. 음성 입력과 답변 재생의 화면 연결은 후속 작업이다.

기본 화면은 세션 생성 API와 POST /api/turns를 호출한다. 서버는 쿠키와 Origin을 확인하고 인증된 sessionId를 runCoordinatedSejongTurn에 전달한다. 승인 응답의 답변·출처를 표시하며, 질문 재시도는 새 requestId를 사용한다. 실패를 샘플 답변으로 대체하지 않는다. 개발 환경의 ?sample=1에서만 샘플 화면을 사용한다.

클라이언트의 최근 대화나 sessionId는 받지 않는다. 최근 승인 대화는 세션 저장소에서 읽는다. 같은 ID·같은 질문은 기존 결과를 반환하고 다른 질문은 409로 거절한다. GET/DELETE /api/requests/{id}로 해당 세션의 요청만 조회·취소할 수 있다. 세션 초기화·만료 또는 취소 후 도착한 결과는 저장하지 않는다.

## 실제 호출 설정

1. 저장소 폴더에서 `git fetch origin`, `git switch dev`, `git pull --ff-only origin dev`로 최신 코드를 받는다. Node 24에서 `npm ci`를 실행한다.
2. `.env.example`을 `.env.local`로 복사한다. 기존 `.env.local`이 있으면 필요한 항목만 수정한다. 이 파일은 Git 제외 대상이다.
3. Ollama를 실행하고 `ollama list`에서 설치된 모델 이름을 확인한다. 모델이 없으면 `ollama pull qwen3.5:4b-q4_K_M`으로 준비한다.
4. `.env.local`에 아래 설정을 넣는다. `OLLAMA_MODEL`은 설치된 4B 모델 이름과 맞춘다. Ollama의 로컬 호출에는 Gemini API 키가 필요하지 않다.

   ```dotenv
   OLLAMA_BASE_URL=http://127.0.0.1:11434
   OLLAMA_MODEL=qwen3.5:4b-q4_K_M
   OLLAMA_TIMEOUT_MS=60000
   USAGE_PROVIDER_PLANS={"ollama:llm_generation":{"mode":"free","maxCostMicros":0}}
   ```

   기존 허용 목록에 확인된 Azure STT/TTS 설정이 있으면 유지하고 `ollama:llm_generation` 항목을 추가한다. 음성 공급자는 기존 선택을 유지한다.
5. `npm run dev`로 실행하고 `http://localhost:3000`에서 질문을 보낸다. 실제 호출 시험에서는 `?sample=1`을 붙이지 않는다. 설정 변경 후 서버를 재시작한다. 운영 서버는 `APP_ORIGIN`에 실제 서비스 origin을 지정해야 한다.

호출 허용 설정 미등록·사용 기록 장애는 503, 요청 한도는 429로 표시한다. Azure 등 외부 공급자는 카드 없는 무료 계정/리소스를 확인한 항목만 허용한다.

## 유진 PC의 첫 글 대화 시험

- `한글은 왜 만들었나요?`, `훈민정음은 처음에 몇 글자였나요?`로 답변과 출처 링크를 확인한다. 현재 승인된 자료는 3개이므로 자료가 없는 질문의 거절과 모델 오류를 구분한다.
- 이어 묻기, 답변 취소, 새 대화와 이전 기록 보기·삭제를 확인한다. 취소·새 대화 뒤 늦게 온 답변이 화면과 서버 기록에 남지 않아야 한다.
- 사용한 커밋, 질문, 결과 화면, 첫 질문과 후속 질문의 소요 시간, 오류 문구를 공유한다. 키나 개인정보는 공유하지 않는다.
- 현재 요청 처리에는 내부 기본 20초·외부 25초 제한이 있고 Ollama 호출 설정은 60초다. 모델이 오래 걸리면 앱 요청이 먼저 끝날 수 있다. `OLLAMA_TIMEOUT_MS`만 늘려 해결됐다고 판단하지 말고 정민·민준이 실제 지연을 보고 코드의 제한을 함께 확인한다.

## 검증 범위

모의 Ollama 응답을 사용하되 실제 생성·자료 선택·출처 연결·승인 저장·사용량 원장 코드 경로를 실행한다. 답변·출처, 최근 대화, 중복 요청, 취소 후 늦은 응답, 세션 소유권, 한도를 자동 시험한다. 프로덕션 HTTP 시험도 격리된 서버와 임시 원장을 사용하며 외부 AI 호출을 하지 않는다.

실제 Qwen 호출과 브라우저 전체 흐름의 최종 검증은 유진 PC의 Ollama에서 진행한다. 자동 시험 통과나 dev 병합을 실제 모델 시험 완료로 기록하지 않는다. 답변 의미 검증(W03-09)은 정민과 범위를 맞춘다. 음성 연결은 후속 작업이다.

## 대화 기록

새 대화 전 질문·답변·출처를 같은 브라우저에 최근 30개까지 보관한다. 이전 대화는 읽기만 가능하며 AI 세션을 복원하지 않는다. 모든 대화 기록 삭제는 보관 기록·현재 화면을 지우고 서버 세션을 삭제한다. 삭제에 실패한 부분은 오류로 안내한다.
