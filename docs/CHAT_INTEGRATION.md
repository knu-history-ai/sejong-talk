# W03-11 글 대화 연결 (#46)

현재 통합 브랜치 codex/46-ai-integration은 PR #45가 병합된 최신 dev를 반영했다. 기존 feat/46-chat-integration 커밋은 보존했다. 실제 Ollama·Qwen 호출 전환은 #48에서 진행하고, 해당 코드를 반영한 뒤 모델이 설치된 노트북에서 #46 화면 통합을 확인한다. 아래 Gemini 설정은 현재 코드 기준이며 Qwen 실행 설정은 #48 안내를 따른다.

기본 화면은 세션 생성 API와 POST /api/turns를 호출한다. 서버는 쿠키와 Origin을 확인하고 인증된 sessionId를 runCoordinatedSejongTurn에 전달한다. 승인 응답의 답변·출처를 표시하며, 질문 재시도는 새 requestId를 사용한다. 실패를 샘플 답변으로 대체하지 않는다. 개발 환경의 ?sample=1에서만 샘플 화면을 사용한다.

클라이언트의 최근 대화나 sessionId는 받지 않는다. 최근 승인 대화는 세션 저장소에서 읽는다. 같은 ID·같은 질문은 기존 결과를 반환하고 다른 질문은 409로 거절한다. GET/DELETE /api/requests/{id}로 해당 세션의 요청만 조회·취소할 수 있다. 세션 초기화·만료 또는 취소 후 도착한 결과는 저장하지 않는다.

## 실제 호출 설정

1. Node 24에서 npm ci를 실행한다.
2. .env.example을 .env.local로 복사한다. .env.local은 Git 제외 파일이다.
3. GEMINI_API_KEY에 본인이 관리하는 키를 입력한다. 브라우저나 GitHub·채팅에 키를 올리지 않는다.
4. 공급자 콘솔에서 카드 없는 무료 계정임을 확인한 뒤에만 아래 항목을 설정한다. 계정 여부를 확인할 수 없으면 기본 {}를 유지한다.

    USAGE_PROVIDER_PLANS={"gemini:llm_generation":{"mode":"free","maxCostMicros":0}}

5. npm run dev로 실행하고 localhost:3000에서 질문을 보낸다. 설정을 바꾼 뒤 서버를 재시작한다. 운영 서버는 APP_ORIGIN에 실제 서비스 origin을 지정해야 한다.

무료 정책 미설정·사용 기록 장애는 503, 요청 한도는 429로 표시한다. 설정 자체는 공급자의 실제 과금 여부를 확인하지 못하므로 무료 계정을 먼저 확인해야 한다.

## 검증 범위

모의 Gemini 응답을 사용하되 실제 생성·자료 선택·출처 연결·승인 저장·사용량 원장 코드 경로를 실행한다. 답변·출처, 최근 대화, 중복 요청, 취소 후 늦은 응답, 세션 소유권, 한도를 자동 시험한다. 프로덕션 HTTP 시험도 격리된 서버와 임시 원장·가짜 키를 사용하며 외부 AI 호출을 하지 않는다.

실제 공급자 호출과 브라우저 전체 흐름의 최종 검증은 실제 키·확인된 무료 계정 준비 후 진행한다. 답변 의미 검증(W03-09)은 정민과 범위를 맞춘다. 음성 연결은 후속 작업이다.

## 대화 기록

새 대화 전 질문·답변·출처를 같은 브라우저에 최근 30개까지 보관한다. 이전 대화는 읽기만 가능하며 AI 세션을 복원하지 않는다. 모든 대화 기록 삭제는 보관 기록·현재 화면을 지우고 서버 세션을 삭제한다. 삭제에 실패한 부분은 오류로 안내한다.
