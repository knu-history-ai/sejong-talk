# 구조화 날짜 자동 평가와 독립 표본 검증

관련: #62 본실험, #71 원문·정답표 검수, #76 표본 독립 검증, #56 실행·기록. 2026-10-15 기준 운영 안내입니다. 구현·자동 검증·CI는 PR #70의 해당 커밋 기록으로 확인하며 실제 본실험·사람 검증 완료와 구분합니다.

## 평가 범위와 대표값

20기사·53문항을 R/P/E/T/V 5방법으로 각 1회 실행하면 **265개 예정 출력**입니다. 전체 출력에는 엄격한 코드 기반 구조화 날짜 평가를 적용합니다. 대표값은 사건 질문의 `structured-date task success`이며, 사람이 답변 전체의 의미를 채점한 정답률이 아닙니다. AI의 의미상 날짜·근거·사건 오류 판정은 보조 결과로 분리합니다.

대표값의 분자는 필수 대상 사건의 구조화 날짜가 모두 고정 정답표에 맞는 사건 문항·회차 수이고, 분모는 실행 전에 고정한 전체 사건 문항·회차 수입니다. 일부 사건만 맞으면 문항 0점입니다. 생성 실패와 완료 응답의 JSON 파싱·스키마 오류도 이 구조화 과제에서는 0점입니다. 표제일 대조 문항은 별도 지표이며, 사건별 점수와 오류율을 문항 대표값으로 바꿔 쓰지 않습니다. 모든 방법을 합친 265개를 방법별 사건 정답률의 분모로 쓰지도 않습니다.

코드는 날짜 값·필수 키·대상 ID·중복·자료/정답/설정 해시·생략 허용 규칙을 확인합니다. 답변 전체가 JSON 객체이거나 전체를 감싼 단일 JSON/무표시 코드블록인 경우만 읽습니다. JSON 앞뒤 설명에서 일부를 골라내거나 문법을 고치지 않습니다. 숫자 문자열의 임의 변환·중복 키의 마지막 값 채택·모르는 날짜의 임의 보충을 허용하지 않습니다. 알려진 값, 자료상 미확정, 출력 누락, 추출 실패는 구분합니다.

구조화 날짜 정답이 자연어 설명의 정답이나 근거의 의미상 지지를 보증하지 않습니다. 인용 구절·위치가 입력에 존재해도 그 인용이 해당 사건·날짜를 뒷받침하는지는 별도 판정입니다. 자동 보고서는 사람 검증 완료·역사적 진실·논문 승인까지 선언하지 않으며 `paperEligible: false`를 유지합니다.

## 방법과 버전 고정

| 방법 | 처리 | 문항당 정상 생성 호출 |
|---|---|---|
| R · `rule-baseline` | 기존 날짜 규칙 | 0회 |
| P · `prompt-baseline` | 날짜·근거를 요구하는 강화 프롬프트 | 1회 |
| E · `evidence-first` | 근거 추출 후 최종 답변 | 2회 |
| T · `render-only` | 동일 P의 날짜·근거를 공통 형식으로 표시 | 추가 0회 |
| V · `evidence-validated` | 동일 P의 인용 위치·지원 날짜 문법을 검사한 뒤 같은 형식으로 표시 | 추가 0회 |

P와 E의 최종 응답에는 같은 **필수 JSON 계약**을 요구합니다. 이전의 선택적 JSON 프롬프트와 달라졌으므로 `METHOD_VERSION = date-methods-v5-structured`로 구분합니다. 이전 실행·프롬프트 조건과 새 실행을 같은 조건의 비교로 섞지 않습니다. 보고서 형식만 바꾼 과거 호환 규칙은 이번 생성 프롬프트 변경에 적용할 수 없습니다. 예전 실행 폴더와 원본·해시는 보존하고 새 계획을 준비합니다.

T/V는 같은 문항·회차의 동일 P 원답변을 공유합니다. T는 표시만 바꾸므로 T−P의 효과는 의미상 답변·표시에서 봅니다. 구조화 날짜 값이 유지되면 P/T의 구조화 점수도 같아야 하며, 달라지면 먼저 추출·변환·채점 경로를 확인합니다. V−T는 같은 표시 조건에서 검사·값 수정의 추가 효과입니다. E−P는 추가 호출을 포함한 방법 전체의 차이입니다. V 통과나 인용 존재를 정답 인증으로 쓰지 않습니다.

정상 생성은 P 53회 + E 106회 = 159회이며 준비 호출 1회는 별도입니다. T/V 추가 생성은 없습니다. E의 첫 호출 실패 등으로 실제 호출 수는 줄 수 있습니다. 예정 출력·완료 출력·실제 호출·정답 수를 구분합니다.

## 실행 전 표본 고정

seed 62, `type-balanced-twelve-v2`를 실행 전에 고정합니다. 날짜 유형별로 가능한 균등하게 **12문항**을 선정하고 각 문항의 R/P/E/T/V 5방법을 모두 검증합니다. 현재 1회 계획은 **12문항 × 5방법 = 60개 예정 표본 출력**입니다. 5유형은 명시 일자(`known-day`), 일자 미확정(`unknown-day`), 잘못된 날짜 전제(`false-date-premise`), 복수 사건(`mixed-events`), 표제일 대조(`header-control`)입니다. 현재 자료에서는 각 유형 2~3문항이며 방법마다 12개입니다. 유형의 동률 배분·문항 선정은 고정 seed의 SHA-256 순위로 결정하며 결과·AI 점수·오류를 사용하지 않습니다.

유형별 문항이 적으면 해당 유형을 모두 포함하고 남은 수를 다른 유형에 균등 배분합니다. 유형 안에서는 이미 많이 선택한 기사를 피하는 것을 우선하지만 서로 다른 기사 12개를 보장하지 않습니다. 실제 선택 기사 수·전체 기사 수·유형별 배분·방법별 예정 수를 기록합니다. 유형 수가 선정 가능한 문항 수보다 많으면 조용히 유형을 빼지 않고 고정을 차단합니다. 일반 예비시험은 자료가 12문항 미만이면 모든 문항을 선정하지만, 본실험 준비기는 정확한 12문항·60개를 만들지 못하면 실행 폴더 전달을 막습니다. 반복을 늘리면 모든 고정 회차를 검증하므로 예정 출력도 늘며 이번 본실험은 1회로 유지합니다.

`sample-manifest.json`에 계획 ID, 자료·정답·기준·설정 해시, seed·선정 버전·문항 목록, 기사 수, 예정 출력 수, 전체/선정 유형별 수를 보존합니다. 실행 결과·진행·호출 기록과 실행 폴더 내보내기 전에 `sample-freeze`를 해야 합니다. 담당자 폴더에 내보내기 기록을 먼저 저장하고 실행 폴더에는 대응표 없이 표본 해시만 연결합니다. 내보낸 뒤에는 결과가 아직 돌아오지 않았어도 표본을 새로 고정하지 못합니다. 파일의 결정적 재현만으로 고정 시점을 증명할 수 없으므로 실행 전 생성 기록과 전달 순서도 남깁니다.

시연·선영 두 사람이 **같은 표본의 완료 출력 각각을 독립 검증**합니다. 각자 최대 60개, 합계 최대 120개 첫 판정입니다. 절반씩 나누지 않습니다. 확정 생성 실패는 계획 표본에 남기고 과제 0점으로 처리하며, 없는 내용을 사람이 채점하지 않습니다. 따라서 실제 사람 판정 수는 완료 표본 출력 수에 따라 줄 수 있습니다. 시연의 추가 답변 검증은 요청 상태이며 #71 자료 검수 수락과 구분합니다. 선영은 10/15 수락했으며 10/16 중 진행한다고 했습니다. 완료 시각은 미확정입니다.

민준은 자료·정답표와 조건·표본 고정 확인, 익명 검증 자료·빈 양식·작성 예시 준비와 배포, 판정 수합·이견 정리 진행·분석·논문 작성을 맡습니다. 두 사람의 독립 첫 판정에는 참여하지 않으며 판정을 대신 작성하거나 임의로 고치지 않습니다. 도구 담당은 코드·검증·실행 폴더 준비·자동 평가·판정 파일 등록·집계를 맡습니다. 정민에게 독립 검증을 중복 배정하지 않습니다. 유진은 준비된 명령 실행·기록·전체 폴더와 오류 전달만 맡으며 설정·자료 검수·내용 채점·집계를 맡지 않습니다.

60개는 이번 작업량의 상한이지 검증 충분성을 입증하는 수가 아닙니다. 유형을 포함해도 드문 오류를 모두 찾는 것은 아닙니다. 독립 단위는 표본에 실제 포함된 기사이며 60개 출력이나 두 사람의 120개 판정을 독립 사례 수로 쓰지 않습니다. 균형 표본은 전체 유형의 비율과 다르므로 전체 내용 정답률로 외삽하지 않습니다. 오답을 정답으로 받아들인 사례, 방법별 편향, 작은 차이·사람 판정에 따른 방법 순위 변동은 추가 진단 검증 또는 탐색적 주장으로 다룹니다. 추가 검증은 원래 표본을 바꾸거나 조용히 합산하지 않고 선정 사유·범위를 별도로 보고합니다. 정해 놓지 않은 자동 합격 임계값을 만들지 않습니다.

기존 `article-one-v1`의 100개 표본·판정·결과는 보존하고 해당 버전으로 재검증합니다. 새 CLI 고정은 v2만 사용하며 기존 파일을 60개로 덮어쓰거나 실행·전달 후 소급 변경하지 않습니다. 새 표본에는 새 담당자 폴더와 실행 전 고정 기록이 필요합니다.

## 담당자 명령과 전달 순서

아래 준비·등록·집계 명령은 민준·도구 담당자용입니다. 시연·선영은 전달받은 판정 양식만 작성해 각각 돌려주며 이 명령을 실행하지 않습니다. 유진에게는 아래에 따로 표시한 실행 명령 하나만 전달합니다. 새 명령의 소스와 운영 계약을 정리한 것이며, 이 문서만으로 전체 명령 실행·CI 통과를 주장하지 않습니다. 실제 승인 자료·폴더로 검증한 뒤 사용합니다.

1. #71의 **전체 20기사·53문항** 원문·정답표 검수를 마칩니다. 표본 검증으로 자료 검수를 축소하지 않습니다. 승인·검수자 기록이 있는 `final/approved` 자료와 고정 방법·모델·설정으로 새 계획을 만듭니다.
2. `prepare-date-main.mjs`가 사전 표본을 고정하고 정답 없는 실행 폴더를 내보내도록 준비합니다.

```sh
node "./scripts/prepare-date-main.mjs" --dataset "검수된 모델입력.json" --gold "검수된 정답표.json" --private-dir "담당자 전용" --out "유진님 실행폴더"
```

일반 `prepare`로 계획을 만드는 담당자는 실행 전에 별도로 다음을 수행합니다. 본실험 준비 스크립트가 이미 고정한 표본을 다시 덮어쓰지 않습니다.

```sh
npm run eval:date -- sample-freeze --dir "담당자 전용"
npm run eval:date -- export-operator --dir "담당자 전용" --out "유진님 실행폴더"
```

정답이 든 담당자 `plan.json`·표본 대응표·채점 파일은 전달하지 않습니다. 유진님은 Node.js 24와 지정 Ollama 모델을 준비한 전달 폴더에서 아래 명령만 실행합니다. 설정·정답·채점 칸을 바꾸지 않고 완료·오류·중단 모두 전체 폴더와 오류를 돌려줍니다.

```sh
node "./run-evaluation.mjs"
```

3. 담당자가 원본을 보존해 가져오고 실행 상태·입력·해시를 확인합니다. 미확인 상태는 로그와 원문으로 별도 해결합니다. AI를 실행한다면 채점기·설정·재시도·대표 출력 규칙을 먼저 고정합니다.

```sh
npm run eval:date -- import-run --dir "담당자 전용" --file "돌려받은 폴더/run.json"
npm run eval:date -- code --dir "담당자 전용"
npm run eval:date -- ai --dir "담당자 전용" --model "고정된 로컬 채점모델"
npm run eval:date -- automatic-report --dir "담당자 전용"
npm run eval:date -- sample-packets --dir "담당자 전용"
```

AI는 보조이며 미실행이면 미실행으로 표시합니다. `automatic-report.json`, `automatic-comparison.json`, `automatic-evaluation-cost.json`은 전체 구조화 과제 결과·같은 실행 내 방법 비교·평가 비용입니다. 사람 검증 보고서와 분리합니다. 코드 진단의 예비 `date`만 복사하지 말고 엄격한 구조화 계약을 적용한 `dateScore`를 사용합니다.

생성 모델과 같은 Qwen을 채점에도 쓰면 자기 선호·공통 오류 가능성을 기록하고 독립 채점기라고 주장하지 않습니다. 기존 legacy `core.accuracy`는 사람 최종 내용 정답률이며 새 자동 `primary`와 다른 지표입니다. 두 값을 같은 정답률로 비교하거나 합치지 않습니다.

AI를 사용한 보고서는 `ai.json`, `ai-start.json`, `ai-calls`도 함께 보존합니다. 원본 응답으로 점수·근거·이유·부분 실패를 다시 계산하고, 실제 호출 기록의 모델·설정·프롬프트·응답·토큰과 대조합니다. `automatic-evaluation-cost.json`의 `aiProvenance`는 이 기록 간 일치 증거이며 외부의 독립 실행 인증은 아닙니다. 출처가 다르거나 호출이 아직 미확인인 상태는 단순한 AI 내용 판정 실패와 구분해 담당자가 확인합니다. 기록을 고쳐 맞추거나 미확인 호출을 임의 재실행하지 않습니다.

4. 민준·도구 담당이 `sample-review-share`와 작성 예시를 시연·선영에게 각각 전달합니다. 실제 본실험용 검증 자료는 결과를 받은 뒤 준비하며 이미 전달된 것으로 처리하지 않습니다. `sample-review-private.json`, 담당자 계획, 코드/AI 점수, 방법·생성 설정·대응표와 상대 판정은 검토자에게 가립니다. 두 검토자는 같은 입력·답변을 무작위 익명 ID로 보고 각자 첫 판정을 저장합니다.

검토자는 `packets.json`의 사료·질문·고정 정답/기준·최종 답변을 보고 `blank-review.json`을 각자 복사해 작성합니다. 각 파일의 `reviewerId`는 `시연` 또는 `선영`으로 일관되게 적고, 실제로 독립·가림 조건을 지켰는지 확인한 뒤 `independent`·`blind`를 기록합니다. 맞음/틀림·비적용·보류와 짧은 근거는 아래의 판정 기준을 따릅니다. 첫 판정 제출 전 서로 답을 맞추지 않으며 민준에게 각자의 파일을 따로 전달합니다. 아래 파일 이름은 예시이며 실제 받은 파일 경로와 검토자 ID를 맞춰 등록합니다.

```sh
npm run eval:date -- import-sample-review --dir "담당자 전용" --file "시연-첫판정.json" --reviewer "시연"
npm run eval:date -- import-sample-review --dir "담당자 전용" --file "선영-첫판정.json" --reviewer "선영"
npm run eval:date -- sample-finalize --dir "담당자 전용"
```

이견·보류는 첫 판정을 덮어쓰지 않고 별도 합의 파일에 원래 판정 해시·근거·변경 사유를 남깁니다. 미제출 항목만 추가 등록하고 기존 첫 판정을 다시 제출하지 않습니다.

```sh
npm run eval:date -- sample-finalize --dir "담당자 전용" --adjudications "표본-합의.json" --out "담당자 전용/sample-final-resolved.json"
npm run eval:date -- sample-report --dir "담당자 전용" --final "담당자 전용/sample-final-resolved.json"
```

`sample-report.json`은 사전 표본의 두 사람 판정·이견 해결·코드/AI와의 대조입니다. 실행 상태 확인본을 사용했다면 해당 명령에 같은 `--run`을 지정하고 계획·실행·AI·자동 보고서·표본 파일의 출처 해시를 맞춥니다. 기존 보고서·첫 판정·실행 파일을 고쳐 맞추지 않습니다.

## 사람 양식의 두 판정

| 양식 필드 | 판단 대상 | 검증 대상 |
|---|---|---|
| `structuredDate`, `structuredReason` | 엄격한 JSON 날짜 과제가 맞는지와 이유 | 코드 `dateScore` |
| `date`(semantic date), `evidence`, `reason` | 최종 답변 전체의 의미상 날짜·근거 | AI 날짜·근거 보조 판정 |
| `events[].date`, 적용 오류 플래그, `reasons` | 사건별 의미상 날짜·오류와 근거 | AI 사건별 보조 판정 |

`structuredDate`는 코드 점수를 보지 않고 JSON 구조·모든 대상·날짜 정밀도·고정 생략 규칙을 독립 대조한 0/1입니다. `structuredReason`을 함께 씁니다. 의미상 날짜가 맞다는 이유로 형식 오류의 구조화 점수를 1로 주지 않습니다. 반대로 구조화 날짜가 맞아도 설명이 모순되거나 엉뚱한 사건·근거를 쓰면 의미 판정은 다를 수 있습니다.

의미 판정은 구조화 필드와 표시 설명을 포함한 최종 답변 전체를 봅니다. 문항 날짜는 필수 사건 모두가 맞아야 1이고 근거는 모든 필수 사건·답한 정밀도를 지지해야 1입니다. 사건별 `unsupportedDay`, `missingKnownDay`, `headerConfusion`은 고정 정답표의 `eligibility`가 적용되는 항목만 판정합니다. 비적용은 null/N/A, 판정 불가는 null/미해결이며 0점으로 메우지 않습니다. 각 점수·오류에는 답변·사료의 표현과 이유를 남깁니다.

기존 날짜 정밀도·동등 표현·생략 허용·달력 기준은 유지합니다. 월만 묻는 질문에 일자 설명을 새 필수로 만들지 않습니다. 월까지 확인되는 사건의 근거 없는 일자·월말 단정, 질문이 요구한 명시 일자 누락, 표제일의 사건일 사용, 일부 사건 누락은 각각 구분합니다. 인용 존재와 의미상 지지는 별개입니다.

기본은 완료 표본 출력별 두 사람의 각각 판정입니다. **중복 판정 자동 재사용은 구현됐다고 가정하지 않습니다.** 수동 재사용은 사료·질문·대상·정답/기준·제한된 평가 입력과 최종 답변 전체가 정확히 같은 경우만 허용합니다. 각 검토자가 자기 판정을 독립 작성하고 원래 실행·방법·문항·회차·대표 답변·판정 ID/해시의 연결표를 보존해야 합니다. 조건을 확인하지 못하면 각 기록을 따로 판정합니다. 표본 수·방법별 분모는 줄이지 않습니다.

## 실행·형식·판정 상태

| 상태 | 전체 구조화 자동 결과 | 의미상 판정·표본 검증 |
|---|---|---|
| 생성 실패·시간초과로 종료 | 고정 분모에서 과제 0점. 부분 답변보다 실패 상태 우선 | 부분 답변을 완료 내용으로 채점하지 않음. 원문·오류·비용 보존 |
| 완료했지만 JSON 파싱·스키마 오류 | 과제 0점, 생성 상태는 `completed` 유지 | 읽을 수 있는 내용은 독립 판정. 의미 점수를 자동 0으로 바꾸지 않음 |
| `unknown`·미실행 | 자동 확정 보고서 금지. 임의 0·제외 금지 | 상태·미실행 해결 전 검증 완료 선언 금지 |
| AI 일부 판정 실패 | 코드 점수·생성 상태 유지 | 해당 필드만 failure/미판정, coverage에서 드러냄. 유효 필드는 유지 |
| AI 호출 실패·시간초과·출력 전체 해석 불가 | 코드 점수·생성 상태 유지 | 해당 출력의 모든 적용 판정 항목 failure. 내용 0점 아님 |
| 사람 미제출·보류·미해결 이견 | 실행 상태가 확정됐으면 전체 자동 계산은 별도로 가능 | `sample-report` 검증 완료 차단. 전체 자동 계산 실패로 바꾸지 않음 |

AI 재시도는 생성 재시도와 분리합니다. 처음 해석 가능한 AI 출력을 대표로 유지하며 일부 판정이 빠졌다는 이유로 재호출해 유리한 결과를 선택하지 않습니다. 호출 실패·시간초과·전체 해석 불가에만 실행 전 고정한 재시도 규칙을 적용합니다. 같은 항목은 검증 분모에 한 번만 세고 모든 시도·원문·비용을 보존합니다.

시연·선영은 두 사람의 첫 판정이 각각 저장·고정될 때까지 방법·설정·코드/AI 점수·상대 판정·대응표를 보지 않습니다. 민준은 첫 판정에 참여하지 않고 배포·실행 확인에 필요한 대응표·점수를 관리하되 검토자에게 공유하거나 판정을 유도하지 않습니다. 노출됐다면 범위·시각을 기록하고 완전한 익명을 보장했다고 쓰지 않습니다.

두 사람의 첫 판정 파일·작성자·시각·근거를 보존한 뒤 두 검토자가 원문·정답표로 이견을 해결하고, 민준은 이견 정리와 기록 수합을 진행합니다. 원래 파일을 덮어쓰지 않고 최종 판정·변경 사유를 별도 기록합니다. 해결되지 않으면 첫 두 판정에 참여하지 않은 제3 검토자를 별도로 정하고 수락을 확인합니다. 미확보·미해결은 표본 미채점으로 유지하며 AI 동의나 단순 다수결로 확정하지 않습니다. 제3 검토자는 미정이며 민준·정민·유진에게 자동 배정하지 않습니다. 민준도 첫 판정 담당에서 빠졌다는 이유만으로 제3 검토자가 되지는 않습니다.

## 보고·비용·해석의 한계

전체 구조화 자동 결과, AI 보조 결과, 사람 표본 결과를 별도 표로 냅니다. 코드↔사람은 구조화 날짜를, AI↔사람은 의미상 날짜·근거·적용 사건 오류를 표본 범위에서만 대조합니다. `사람 0/1 × 자동 0/1/failure`, 실패 포함 일치율, 유효 판정 내 일치율, 판정 coverage, 방법·유형별 분자/분모를 남깁니다. 오류 플래그의 1은 ‘오류 있음’이므로 정답 점수와 오수락 방향이 반대입니다. 코드 통과·사람 의미상 실패는 같은 척도의 일치 실패가 아니라 구조화/의미 간격으로 설명합니다.

사람 결과를 미검토 205개에 복사하거나 265개 전체의 사람 내용 정답률로 외삽하지 않습니다. 이번 문서는 모집단 보정·PPI·신뢰구간·통계적 유의성을 승인하지 않습니다. 전체 실험은 기사 20개이며 표본의 독립 단위는 실제 선정 기사입니다. 같은 질문의 5방법 출력과 반복은 독립 표본이 아닙니다. 기사별 동일 가중 결과·유형별 범위·기존 개발 노출·희귀 오류 누락을 함께 적습니다.

T/V 서비스 비용은 P 생성 비용과 각 후처리를 포함하고 실제 배치 비용은 공유 P를 한 번만 셉니다. 완료 응답 지연 중앙값/p95와 실패·추출·재시도를 포함한 전체 시간·호출·토큰을 구분합니다. 준비 호출·코드·AI·사람 평가 비용은 각각 별도입니다. 알 수 없는 호출·토큰·시간은 N/A와 부분합이며 0으로 추정하지 않습니다. 재개 배치의 불완전한 경과 시간·준비 이력을 완전한 값으로 바꾸지 않습니다.

기존 `packets / import-review / finalize / report / validate-judge`는 **전체 사람 최종 채점 legacy 경로**로 보존합니다. 완료 답변 전체의 두 사람 판정·이견 해결·해시·비용 검증 요건을 완화하지 않습니다. 새 표본 파일을 legacy 전체 판정으로 넣거나 legacy 보고서를 전체 자동 보고서로 바꾸지 않습니다. 기존 안내는 [평가도구](date-evaluation-tool.md), 방법·파생·비용 계약은 [V·T](date-vt-methods.md)를 참고합니다.

시연님의 #71 검수 수락은 #76 추가 답변 검증 수락과 다릅니다. 선영님의 수락은 10/16 중 진행이며 낮 완료 약속이 아닙니다. 유진님은 실행·기록·전체 폴더/오류 전달만 맡습니다. 10/15 저녁 실행, 10/16 낮 첫 판정 수합·저녁 분석, 10/17 원고 완성, 10/18 교수님 전달, 10/23 제출은 2026년 KST 작업 목표이며 완료·수락·회신·제출 약속이 아닙니다. 판정이 늦어지면 이견 정리·분석 목표도 조정하고 미제출을 임의 0점이나 완료로 바꾸지 않습니다. 자료 승인·본실험 실행·독립 검증·논문 제출의 완료 증거를 각각 남깁니다.
