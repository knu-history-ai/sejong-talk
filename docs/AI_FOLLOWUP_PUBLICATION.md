# 후속 질문과 답변 공개 검사 — #74 / #75

## #74 문맥에 맞는 자료 선택

`집현전은 어떤 곳이야?`에 이어 `거기서는 뭘 했어?`라고 물으면 현재 세션의 최근 grounded 답변에 연결된 사실 ID를 다시 조회한다. 승인 상태, 인물 ID, 연결 출처가 현재 저장소에도 유효해야 한다. 이전 모델의 답변 본문은 자료 선택에 사용하지 않으며 생성 프롬프트에도 다시 넣지 않는다.

- 명시적으로 다른 주제를 묻는 질문은 그 질문으로 자료를 새로 선택한다.
- 최근 10턴 안의 연속된 동일 사실 ID와 명시적 공통 주제를 확인한다. 최대 6개 사실 제한을 유지한다.
- 문맥 없음, 여러 주제, 승인 취소·자료 삭제·출처 누락, 일상 대화로 주제가 끊긴 경우에는 서버가 대상의 이름을 되묻는다. 이 경로에서는 모델을 호출하지 않는다.
- 자동 연결은 `거기서는 뭘 했어?`, `그곳에서는 무엇을 했나요?`, `그것은 왜 만들었어?` 등 명시된 짧은 표현으로 제한한다. 모든 한국어 생략·대명사를 해석하는 기능은 아니며, 인식하지 못한 지칭은 추측하지 않는다.
- HTTP 계층이 인증한 세션의 최근 대화만 전달한다. 새 세션·초기화 이후 다른 사용자의 이력은 사용하지 않는다.

## #75 공개 전 본문 검증

`validateAnswerDraft`는 형식·사실 ID·출처(및 #73 병합 뒤 말투)를 확인하는 동기 검사다. 이것만으로 의미상 사실성을 확인했다고 간주하지 않는다. 운영 생성 경로는 추가로 `verifyForPublication`을 통과해야 모델의 본문을 공개한다.

1. `fallback` / `insufficient`는 모델 본문을 버리고 서버 고정 안내로 바꾼다.
2. 존재하지 않거나 현재 승인되지 않은 사실 ID, 출처 누락은 모델 검증 전에 차단한다.
3. `conversation`도 별도 내용 검사에 보낸다. `non_historical` 판정과 빈 사실 목록을 확인한 경우에만 본문을 유지한다. 일반 대화를 일괄 차단하지 않는다.
4. `grounded`는 실제 승인 사실의 문장과 후보 본문 전체를 검증 모델에 전달한다. 모든 역사 주장이 뒷받침된다는 `supported` 판정과 인용 ID 일치를 확인해야 본문·출처를 유지한다. 하나의 올바른 ID를 붙여 덧붙인 주장을 숨기는 것을 허용하지 않도록 명시한다.
5. 불확실·근거 없음·잘못된 JSON·검증 오류·시간 초과는 원문 대신 고정 안내로 처리한다. 취소된 요청은 기존 coordinator가 대화 저장을 막는다.

검증 호출은 기존 Ollama 어댑터와 사용량 ledger를 사용하며 `llm_verification` 단계로 호출 횟수·토큰을 별도 기록한다. 최대 5초, 재시도 0회이며 기존 턴 전체 시간·세션·취소 제한을 늘리지 않는다. 생성에 시간이 많이 걸리면 남은 턴 시간 때문에 검증이 더 일찍 취소될 수 있다. 판정 로그는 정해진 reason 코드만 남기며 질문·답변·공급자 오류 본문·API 키를 기록하지 않는다.

## 실행 설정과 평가 한계

로컬/무료 Ollama 사용 확인 후 기존 `USAGE_PROVIDER_PLANS`에 다음 항목을 **추가**한다(다른 공급자 설정을 덮어쓰지 않는다).

```json
"ollama:llm_verification": { "mode": "free", "maxCostMicros": 0 }
```

미설정이면 검증 호출은 기존 정책에 의해 차단되고 모델 후보 대신 안내문을 반환한다. 생성 호출만 허용하던 환경은 이 설정을 추가해야 한다. 유료 호출 정책은 변경하지 않는다.

추가 호출 1회의 지연과 토큰이 발생한다. 생성 모델과 같은 Ollama 모델을 별도 요청으로 사용하며, 독립된 모델 간 교차 검증은 아니다. LLM 판정 자체는 오판할 수 있으므로 자동 테스트가 역사적 정확성이나 환각 차단율을 증명하지 않는다.

이번 테스트는 실제 서버 코드와 모의 공급자 응답을 이용해 자료 연결, 공개 결정, 세션 분리, 취소, 사용량 기록을 검증한다. 실제 Qwen 서버 연결이 없어 생성 품질·검증 정확도·5초 내 처리 가능성은 미확인이다. 특히 #75는 실제 모델로 잘못된 역사 문장, 올바른 사실 ID와 허구 혼합, 정상 일상 대화, 정상 근거 답변을 시험하고 공개 전에 오차단·오승인·지연을 검토해야 한다. 이 단계가 끝나기 전 완료 처리하지 않는다.

```sh
node --conditions=react-server --test tests/*.test.mjs
npm run lint
npm run typecheck
npm run build
node --test --test-concurrency=1 tests/integration/*.test.mjs
```

PR #73의 말투 수정, #89 평가 도구, Bedrock 스트리밍·끼어들기 취소 PoC는 이 변경과 별개다.
