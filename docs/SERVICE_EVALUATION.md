# 서비스 평가 시제품 — #89

`feat/89-service-evaluation`의 범위는 기존 고정 질문 실행기를 이용한 서비스 답변 평가다. 앱의 생성·자료 선택·말투·근거 검사 로직, 날짜 논문 자료·결과, 음성 UI는 바꾸지 않는다.

## 기준과 입력·출력

- 질문: `evals/sejong/fixed-questions.json`. 기존 Q01·Q03·Q05를 보존하고 총 10개로 확장했다. Q11·Q12의 앞선 대화는 고정 입력이다.
- 기준: `scripts/service-evaluation-criteria.json`, `service-eval-v1-draft`. 기대 동작·허용/차단 예시·적용 AI 항목을 담았다. 허용 예시는 유일한 정답 문장이 아니다.
- **정민의 입력·출력 형식 확인과 민준의 기준 검토 전 초안**이다. 검토 후 기준을 바꾸면 버전도 올리고 새 실행으로 남긴다.
- 승인 사실만 기존 선택기로 선택한다. `pending`은 사용하지 않는다. 후속 문맥 선택 실패는 #74 담당 범위이므로 여기서 고치지 않는다.
- 기존 실행기처럼 서비스의 `parseAnswerDraftFromText` → `validateAnswerDraft`를 거친 공개 답변을 평가한다. HTTP 세션·취소·사용량 통합 시험은 아니다. 기존 검증기가 차단 이유를 구조화해 주지 않으면 `미확인`으로 남긴다.
- 결과 JSON은 후보 원문·공개 답변·출처·서버 검증 상태·생성 오류·형식 오류·채점 오류를 구분한다. 생성/채점 시간·사용량·비용을 따로 보존한다. 실제 비용이 확인되지 않으면 `null`이며 0달러로 추정하지 않는다.

## 준비와 수동 실행

Node 24와 `npm ci`가 필요하다. 기본 실행은 고정 모의 응답과 고정 모의 채점만 사용한다. API·로컬 모델을 호출하지 않는다.

```powershell
npm.cmd run eval:ai -- --mock
```

출력은 `evals/sejong/results/run_*.json`과 같은 이름의 Markdown 보고서다. 실행별 새 이름을 쓰며 기존 파일을 덮어쓰지 않는다. 출력에는 질문·이력·승인 자료·설정·채점 프롬프트 식별 해시와 Git 커밋·미커밋 diff 해시를 남긴다.

실제 호출은 별도 수동 실행이다. 공급자·모델·계정·예상 비용은 #86에서 확인해야 한다. 현재 연결은 기존 Ollama 요청 모듈을 사용하며 Bedrock이나 새 상용 공급자를 추가하지 않았다. 생성과 채점은 별도 호출·단계다. `EVAL_JUDGE_MODEL`로 채점 모델을 따로 지정할 수 있다. 미설정이면 생성 모델과 같으며, 이 경우 모델 독립성을 주장하지 않는다.

```powershell
# 기존 USAGE_PROVIDER_PLANS의 허용 설정도 필요하다. 실제 호출은 자동으로 실행하지 않는다.
$env:EVAL_JUDGE_MODEL = '팀에서 확인한 모델 식별값'
npm.cmd run eval:ai -- --live --judge=ollama --change="비교 대상 생성 프롬프트 변경 설명"
```

실제 생성에 `--judge`를 생략하면 AI 항목은 미채점이다. 실제 생성과 모의 채점을 섞는 조합은 허용하지 않는다. 모델 이름은 설정값 기준이며 실제 가중치 동일성까지 검증한 것은 아니다.

## 수정 전후 비교

```powershell
npm.cmd run eval:ai -- --before="evals/sejong/results/이전.json" --after="evals/sejong/results/이후.json"
```

질문·이력·기준·승인 자료·생성 설정·채점 설정·실제 선택 사실·문항 집합이 다르면 `comparable: false`와 불일치 항목을 출력한다. 이후 실행의 `--change`도 필수다. 비교 결과는 두 실행의 항목별 분자·분모를 나란히 제공하며 전체 성공률이나 자동 개선 결론을 만들지 않는다. 코드·생성 프롬프트 변경은 두 실행의 커밋·diff·프롬프트 해시로 검토한다.

코드 검사: 공개 답변 계약, 상태 기록, 승인 사실 ID, 사실과 출처의 실제 연결, 기대 분류/필수 ID. ID가 있어도 내용이 틀린 답변은 별도 AI의 `grounding`에서 확인한다.

AI 평가: `persona`(인물·말투), `relevance`(질문 적합성·잘못된 거절), `grounding`(제공 승인 자료의 내용 지지). 각 질문의 `aiItems`가 적용 대상을 고정한다. 판정은 `pass / fail / indeterminate`, 실행·형식 오류는 `ungraded`로 기록한다. 일부 항목만 잘못되면 나머지 유효한 판정은 보존한다.

- 통과율 = 통과 / (통과 + 실패).
- 평가 가능 비율 = (통과 + 실패) / 적용 대상.
- 판정불가·미채점은 별도 개수다. 분모 0은 `계산 불가(0건)`이다.
- 모의 판정은 허용 예시에 미리 정한 레이블이다. 실제 AI 채점 정확도 검증이나 임의 답변의 의미 분석이 아니다.

## 대표 사례와 검증 상태

`tests/service-evaluation.test.mjs`에는 출처 URL 변조·미승인 사실·잘못된 거절·채점 부분 오류·0건 분모·비교 조건 불일치 검사를 작성했다. 실제 채점기를 검증할 때는 자기소개/3인칭 자기 지칭, 올바른 ID에 잘못된 내용, 정상 인용, 평가 중단을 함께 확인한다.

고정 정답·오답 5개와 예정 판정은 `tests/fixtures/service-judge-calibration.json`에 있다. 다음 모드는 답변 생성을 호출하지 않고 해당 후보를 기존 검증기에 통과시킨 뒤 채점한다. 예정 판정은 AI 프롬프트에 넣지 않고, 결과의 `calibrationMismatches`에 차이를 남긴다. 모의 모드는 예정 레이블을 사용하는 입출력 점검용이며 채점 정확도 근거가 아니다.

```powershell
# 아래 명령은 현재 실행하지 않았다.
npm.cmd run eval:ai -- --mock --calibrate
# 팀 확인 후 실제 채점기를 고정 예시에만 연결하는 수동 명령
npm.cmd run eval:ai -- --live --judge=ollama --calibrate
```

현재는 사용자 지침에 따라 코드 정적 검토·구문·타입 확인만 수행한다. 모의 실행·테스트 실행·실제 모델/API 호출·음성 청취는 수행하지 않았다. 따라서 실행 결과 예시와 실제 AI 성능은 미검증이며, 시제품을 이슈 완료로 표시하지 않는다. 게임 실행 및 CUDA/GPU 검증도 하지 않는다.

정민 리뷰 대상: 위 후보/공개 답변 구분, `serverStatus`와 차단 이유 미확인 처리, AI 호출 형식과 항목별 부분 실패. 민준 리뷰 대상: 10개 질문·항목 적용 범위·허용/차단 예시·통과율 분모. 리뷰 요청은 사용자 확인 후 게시한다.
