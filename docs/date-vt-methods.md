# V·T 비교 계약과 검증

현재 평가 기준은 [구조화 날짜 자동 평가와 독립 표본 검증](date-automatic-sample.md)입니다. 전체 예정 출력의 strict structured-date 코드 대표값, AI 의미 판정 보조값, 실행 전 고정한 100개 예정 출력의 두 사람 독립 검증을 구분합니다. 아래 파생·상태·비용 계약은 유지하며, 전체 완료 답변의 사람 최종 판정과 `metricVersion: 2` 보고서는 기존(legacy) 경로입니다. P/E 최종 응답은 같은 필수 JSON 계약의 `date-methods-v5-structured`로 고정하며 이전 선택적 JSON 실행과 섞지 않습니다.

관련: #62 평가도구, #71 자료 검수, #76 독립 사람 채점. 앱 통합시험과 별개인 MODEL 실험입니다.

## 비교 방법

| ID | 방법 | 문항당 정상 모델 호출 |
|---|---|---|
| rule-baseline (R) | 기존 날짜 규칙 | 0회 |
| prompt-baseline (P) | 날짜 구분·근거를 요구하는 강화 프롬프트 | 1회 |
| evidence-first (E) | 근거 추출 후 원문과 대조하는 답변 | 2회 |
| render-only (T) | 같은 P의 구조화된 값·근거를 공통 형식으로 표시 | 추가 0회 |
| evidence-validated (V) | 같은 P의 인용 위치·지원 날짜 문법을 검사한 뒤 T와 같은 형식으로 표시 | 추가 0회 |

T·V는 같은 문항·반복의 **동일한 P 원본**을 사용합니다. P의 호출·원답변·해시를 바꾸거나 새로 생성하지 않습니다. 모든 생성의 고정 순서를 먼저 수행한 뒤 T·V를 파생하므로 무작위 순서에서 원본보다 먼저 처리되는 문제가 없습니다. 재개해도 기존 P를 재호출하지 않습니다. E는 기존 2단계 프롬프트를 유지하며 V를 추가 적용하지 않습니다. R도 기존 규칙을 유지합니다.

53문항·1회라면 결과는 5방식 × 53 = 265개입니다. 생성 호출은 P 53 + E 106 = 159회이며 준비 호출 1회는 별도로 기록합니다. 재시도 0회이며 E의 첫 호출 실패 시 두 번째를 하지 않으므로 실제 호출 수는 더 작을 수 있습니다.

## V가 확인하는 것과 확인하지 못하는 것

V는 정답표 없이 원문과 P가 출력한 인용을 사용합니다. 숫자로 적힌 연·월·일, 명시적 월·일, 인용된 표제에 연결된 이달/이날 등 지원 문법만 다룹니다. 실제 인용 범위와 문자열을 UTF-16·끝 위치 제외 기준으로 검사합니다. 월만 뒷받침되면 월을 유지하고 근거 없는 일자 정밀도를 제한합니다. 확인되는 일자는 보존합니다.

인용이 실제 존재한다는 사실은 **그 사건을 설명하는 근거라는 뜻이 아닙니다.** 의미상 사건 연결, 사료 전체에서 날짜가 없는지, 복잡한 상대 날짜·범위·윤달·한자 날짜·상충 인용 등은 완전히 해결하지 않습니다. 지원하지 못하거나 인용이 틀리면 원래 값을 보존하고 감사 기록에 미검증 사유를 남깁니다. 미검증을 모두 null이나 정답으로 바꾸지 않습니다. 지원 문법의 보수적 범위와 기존 R의 다른 추출 범위는 논문 한계로 적습니다. 범용 날짜 해석기·새 학습 모델의 성능으로 주장하지 않습니다.

T는 날짜나 인용을 검증·수정하지 않습니다. T·V는 출력 값이 같으면 같은 답변을 만드는 공통 표시 형식을 씁니다. 방법명·검사 통과 여부는 최종 답변에 넣지 않고 별도 `derivation.audit`에 남깁니다. 원 P의 설명은 원본 기록에 보존하며 T·V의 의미 판정 대상은 변환 후 표시 답변 전체입니다. P/E는 원응답 전체를 봅니다. T−P는 의미상 답변·표시 변경의 효과이며 구조화 날짜가 같으면 구조화 점수도 같아야 합니다. V−T는 이 구조에서 검사·값 수정의 추가 효과이고 E−P는 추가 호출을 포함한 방법 전체의 차이입니다.

## 상태와 원본 보존

- 정상 응답이 JSON 본문 또는 전체를 감싼 단일 JSON/무표시 코드블록이면 구조를 읽습니다. 문법을 고치거나 설명에서 JSON을 골라내지 않습니다.
- 형식을 읽지 못하면 T·V 모두 원 P 답변을 그대로 보존합니다. 생성 완료 상태를 유지하며 `not-applied`로 남깁니다. 내용 점수는 사람이 판단합니다.
- null, 일자 미확정 표시, 대상 미출력을 구분합니다. 일자 null만으로 사료상 일자 부재를 선언하지 않습니다.
- P가 실행 실패면 T·V도 실패입니다. 같은 고정 분모에서 자동 0점입니다. 부분 답변을 완료로 바꾸지 않습니다.
- P가 미확인·미실행이면 T·V도 같은 상태이며 최종 집계를 막습니다. 후처리 프로그램 오류도 원문을 보존하고 미확인으로 남깁니다.
- 담당자가 원 P의 실행 상태를 근거와 함께 확인하면 별도 확인본에서 파생 답변·연결 해시를 다시 만듭니다. 원 실행은 덮어쓰지 않습니다. T·V만 임의로 완료로 확정할 수 없습니다.

## 비용의 두 관점

방법별 `usage`와 `timing`은 독립 서비스 기준입니다. T·V는 P의 생성 호출·토큰·전체 소요 시간에 각 후처리 시간만 더합니다. 따라서 T·V를 모델 호출 0회짜리 서비스라고 쓰면 안 됩니다. **추가** 호출이 0회일 뿐입니다.

`physicalBatchUsage`는 실제 실험 배치 기준입니다. P 생성을 한 번만 세며 T·V는 실제 후처리 시간만 더합니다. 방법별 비용을 합산하면 공유 생성이 중복되므로 총 실험 비용으로 사용하지 않습니다. 준비 호출은 원기록을 따로 보존하고 AI·사람 채점 비용은 기존 별도 비용 파일에 둡니다. 알 수 없는 토큰은 null과 확인된 부분합을 유지하며 0으로 추정하지 않습니다. 재개 배치는 전체 경과 시간을 완전하게 측정했다고 주장하지 않습니다.

상태 정정으로 T·V를 다시 만들 때도 최초 후처리 시간은 덮어쓰지 않습니다. 추가 작업은 `postprocessInspections`에 누적하고 실제 배치의 항목 처리 시간에 포함합니다. 보고서의 `postprocessInspectionElapsedMs`로 이 비용을 따로 확인할 수 있으며, 최초 서비스 지연 시간에는 섞지 않습니다. 여러 번 재개할 때는 이전 `warmupHistoryComplete`도 `existingWarmupHistoryComplete`로 전달합니다. 누락됐던 준비 이력을 나중에 새 준비 호출 하나가 생겼다는 이유로 완전한 기록으로 바꾸지 않습니다.

## 실행·채점·검수 분담

#62의 대표 지표는 전체 사건 문항 최종 정답률입니다. 새 보고서의 `primary`는 `core.accuracy`와 같고 기사 동일 가중 평균은 `supplementary.articleEqualWeight`에 보조 지표로 남깁니다. `metricVersion: 2`와 지표 정의를 기록하며, 버전이 없는 이전 보고서의 기사 가중 `primary`는 원래 의미와 파일을 그대로 보존합니다. 비교 시 버전별 집계값을 검증하고 문항별 판정으로 차이를 계산합니다.

구현·테스트·폴더 준비는 도구 담당이 합니다. 사용자는 팀원 메시지 전달과 원문 검수·사람 채점을 맡습니다. 시연님의 추가 채점 수락은 별도 확인 사항입니다. 유진님은 실행·기록·전체 폴더 전달만 맡습니다.

코드 검사는 값·위치의 예비 검사, AI는 검증이 필요한 예비 채점입니다. 완료된 답변은 두 사람의 독립 첫 판정과 이견 해결이 끝나야 최종 집계합니다. 미채점을 자동 0점으로 바꾸지 않습니다. 같은 입력·고정 정답/기준·범위·최종 답변 전체가 같을 때만 각 채점자가 자기 판정을 재사용할 수 있으며 방법·문항별 분모는 유지합니다.

## 검증 범위

개발에는 기존 예비 3기사·8질문과 합성 자료만 사용합니다. 최종 20기사·53질문·정답표를 보고 V를 맞추지 않습니다. 기존 후보 일부 노출 이력은 별도 남기며 독립성이 완전히 보장됐다고 주장하지 않습니다.

회귀 시험은 공통 표시, 잘못된 인용·상대 날짜·문장 경계·잘린 날짜·중복/누락 ID·null 상태, P 원본 공유, 실패·미확인 전파, 원본 위변조 거부, 서비스/실배치 비용, 정답 없는 이동형 폴더 실행, 담당자 계획에 반환 결과 등록을 포함합니다. 모의 모델·합성 판정 시험 통과는 실제 Qwen 성능·역사적 정답·사람 독립 채점 완료를 의미하지 않습니다.
