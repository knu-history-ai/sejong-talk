# 세종톡 정량 평가 기준 (초안 v0.1)

작성: 이유진 · 2026-11-12 · 상태: **팀 검토 전 초안**. 기준은 결과를 보기 전에 확정하고, 바꿀 때는 버전을 올립니다.

## 1. 목적과 원칙

최종발표에서 세종톡의 성능을 **수치로** 보여 주는 것이 목적입니다. 기술 스택을 바꾼 앞뒤(예: Ollama/Qwen·Azure 턴 방식 → Bedrock·ElevenLabs 실시간 방식)를 **같은 기준으로** 비교할 수 있어야 합니다.

1. **블랙박스 평가:** 내부 구현은 보지 않고, 같은 입력(질문·음성 파일)을 넣었을 때 나온 출력(사용자에게 보인 답변·출처·음성·시각)만 채점합니다. 그래야 스택을 바꿔도 같은 기준이 그대로 적용됩니다.
2. **고정 세트·고정 기준:** 질문 세트, 정답, 승인 자료 버전, 채점 규칙, 평가 모델·프롬프트는 실행 전에 고정합니다. 결과를 본 뒤 기준을 고쳐 점수를 다시 계산하지 않습니다.
3. **분모를 숨기지 않기:** 모든 수치는 `분자/분모(%)`로 적습니다. 실행·형식 실패는 0점으로 분모에 넣습니다. 기록 누락·미실행은 별도로 "집계 미완료"로 표시합니다.
4. **판정불가 분리:** 통과/실패/판정불가를 구분합니다. 통과율은 `통과 ÷ (통과+실패)`, 평가 가능 비율은 `(통과+실패) ÷ 대상 수`로 따로 적습니다. 이 규칙은 #89와 같습니다.
5. **과장 금지:** 표본이 작으면 "향상"이라고 단정하지 않습니다. 문항별 개선·악화·동일 수를 함께 보고합니다.

> 근거: 우리 KIIT 논문(세종실록 사건 날짜 추출)에서 얻은 교훈입니다.
> ① 날짜 필드가 맞은 것(D0 10/17)과 인용·형식까지 통과한 엄격 성공(5/17)은 크게 달랐습니다.
> ② 추출 실패로 후속 호출이 생략된 것을 비용 절감으로 해석하면 안 됩니다.
> ③ 같은 정답 수(5/17 = 5/17)는 동등성이나 우월성의 증거가 아닙니다.
> ④ 미상 일자를 임의로 채운 것과 판정 불가는 구분해야 합니다.

## 2. 평가 세트

| 세트 | 내용 | 규모(1차 → 발표) | 담당 |
| --- | --- | --- | --- |
| **글 질문 세트** | 인사·자기소개, 승인 자료가 있는 역사 질문, 자료가 없는 질문, 인물·말투 변경 요청, 짧은 후속 질문(앞 대화 고정), 주제 전환, 날짜 질문 | 10 → 60 | 시연님 #89 세트를 공용으로 사용 |
| **날짜 하위 세트** | 논문 형식(연·월·일 + 미상 표시). 승인된 사실 카드의 날짜만 정답으로 사용 | 10 → 20 | 논문 자료 재사용(PR #72 정답표와 겹치지 않게) |
| **음성 세트** | 글 질문 세트 중 10문항을 실제로 읽어 녹음. 조용한 곳/시끄러운 곳 × 2명. 원음은 팀 내부 보관, 저장소 비공개 | 40개 녹음 | 유진 |
| **대화 시나리오** | 3~5턴 실시간 대화(끼어들기 2회 포함) 고정 대본 | 5개 × 3회 | 유진·시연님 |

`pending` 상태 자료는 정답 근거로 쓰지 않습니다. 자료가 부족해서 답하지 못한 경우와, 자료가 있는데 잘못 거절한 경우는 구분합니다.

## 3. 지표

### A. 답변 품질 (글 기준 · 스택 무관)

| ID | 지표 | 정의(계산식) | 채점 방법 |
| --- | --- | --- | --- |
| **A1** | **엄격 과제 성공률** (대표 지표) | 질문별 필수 항목(A2a·A3·A5·A6, 해당 시 A4)을 **모두 통과**한 질문 수 ÷ 계획한 질문 수. 생성·검증 실패는 0점으로 분모에 포함 | 항목 결과 조합 |
| **A2a** | **사료 인용 유효성** | 답변에 붙은 출처 ID가 승인(approved) 자료에 실제로 있는 비율. 출처 수 기준 | 코드 |
| **A2b** | **사료 근거 일치도** | 답변의 역사적 주장이 그 주장에 붙은 승인 사실 카드에 실제로 근거한 비율. 주장 단위 | LLM 평가 + 사람 표본 검수 20% |
| **A2c** | **근거 제시율** | 역사적 사실을 말한 답변 중 유효 출처가 1개 이상 붙은 답변의 비율 | 코드 |
| **A3** | 사실 정확도 | 질문별 핵심 사실(연도·인물·사건)이 정답과 일치하는 비율. 날짜는 알려진 필드만 채점하고 미상 필드는 별도 집계 | 코드(정답표 대조) |
| A3-d | 미상 임의 확정률 | 정답이 "일자 미상"인 필드를 모델이 임의로 채운 비율(논문 4.3절과 같은 정의) | 코드 |
| **A4** | 환각률 | 승인 자료 밖의 역사 주장이 포함된 답변 ÷ 역사 답변 수 | LLM 평가 + 사람 표본 |
| **A5** | 거절 적절성 | 2×2 표로 보고합니다. 답해야 하는데 거절한 비율(**잘못 거절률**)과 거절해야 하는데 답한 비율(**잘못 답변률**)을 따로 계산 | 코드(서버 상태) + 기대 동작 |
| **A6** | 인물 일관성 | 세종 1인칭 유지율. 3인칭 자기 지칭("세종대왕은 ~했다")이나 현대어 이탈이 없는 답변의 비율 | 코드(패턴) + LLM |
| A7 | 형식·검증 실패율 | 서버 검증 차단, 형식 오류, 시간 초과를 원인별 건수로 집계 | 코드 |

- A2a·A2c·A3·A5·A7은 **코드 채점**이라 재현성이 높습니다. 발표에서는 이 지표를 먼저 보여 줍니다.
- A2b·A4·A6은 LLM 채점이므로 정답·오답 예시로 채점기 일치율을 먼저 확인합니다(#89 4절). 확인하기 전에는 "참고치"로 표시합니다.
- "역사사료 사용 정확도"는 **A2a × A2b × A2c 세 개를 따로 보고**합니다. 하나로 합친 점수는 원인을 가립니다(논문 교훈 ①).

### B. 음성·실시간 (스택 전환 비교의 핵심)

| ID | 지표 | 정의 | 측정 |
| --- | --- | --- | --- |
| **B1** | **응답 지연** | 사용자 말 끝 → 첫 답변 음성 재생 시작(ms). p50·p90과 최댓값 | 클라이언트 시각(`state.timing`). 서버 구간(#95: 요청→헤더→본문 완료)은 별도 표 |
| **B2** | **끼어들기 성공률** | 답변 재생 중 사용자가 말했을 때 **1초 안에 재생이 멈춘** 비율 | 대본 시나리오 + 화면 기록. 정지 지연(ms)도 함께 적음 |
| B3 | 끼어든 뒤 답변 정확도 | 끼어든 뒤 새 질문에 맞게 답한 비율(이전 답변을 이어 말하면 실패) | 사람 |
| **B4** | 음성 인식 정확도 | 고정 녹음의 문자 오류율(CER). 역사 용어 인식률(훈민정음·집현전·장영실·측우기 등)은 따로 계산 | 코드(정답 문장 대조) |
| B5 | 음질 | 고정 문장 7개 × 청취자 3명 이상이 1~5점으로 평가(MOS). 역사 용어 발음 오류 수 | 사람 |
| B6 | 연결 안정성 | 대화 시작 성공률, 대화 중 끊김 수 ÷ 대화 시간(분) | 클라이언트 로그 |

- **측정 지점 맞추기:** 기존 턴 방식에는 "말 끝"이 없습니다. 녹음 정지 버튼을 누른 시각을 말 끝으로 보고, 실시간 방식은 음성 인식 확정 시각을 씁니다. 두 정의가 다르므로 표에 반드시 적습니다.
- B4·B5는 기존 STT 5종 비교(`docs/STT_W01_FEASIBILITY.md`)와 TTS 비교(`docs/W01-05-TTS-실험.md`)의 문장·방식을 이어서 써서 과거 값과도 비교합니다.

## 4. 실행·보고 규칙

1. 실행마다 **실행 ID·커밋·세트 버전·자료 버전·모델/설정·환경**을 기록하고, 이전 결과를 덮어쓰지 않습니다.
2. LLM 답변은 같은 조건으로 **3회** 실행해 범위를 보고합니다(WBS W09-03).
3. 비교 대상 외의 조건(질문·자료·평가 프롬프트)은 같게 둡니다. 다르면 "단순 비교 불가"로 표시합니다.
4. 문항별 짝 비교 결과(**개선/악화/동일 수**)를 함께 적습니다. 표본이 작으면 "차이가 확인되지 않음"으로 씁니다.
5. 사람 검수는 누가 몇 건을 봤는지 적고, 독립 검수가 아니면 그렇다고 밝힙니다(논문 4.1절).
