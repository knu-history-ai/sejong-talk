## 2. 실행 및 파일

```sh
npm run dev
# http://localhost:3000/voice-input-test
node --test tests/unit/voice-input.test.mjs
npm test
npm run lint
npm run typecheck
npm run build
```

시험 페이지는 개발 모드에만 열리며 프로덕션에서는 404를 반환한다. 기존 메인 페이지·레이아웃·공통 CSS·package.json은 변경하지 않았다.

- `src/features/voice-input/recorder.ts`: 브라우저 자원/상태 관리, MIME 협상, 제한, 취소 토큰, Blob 생성.
- `mock-transcription.ts`: 700ms 후 고정 예시 글, AbortSignal 취소. 실제 인식 아님.
- `voice-input.tsx`: 녹음 조작, 수정 가능한 질문, 명시적 전송, 실패 시 입력 보존.
- `voice-input-demo.tsx`: 확인한 질문과 전달 횟수 표시. AI 답변이나 서버 전송이 아님.
- `src/app/voice-input-test/page.tsx`: 독립 시험 경로.
- `tests/unit/voice-input.test.mjs`: 기존 TypeScript/Node 내장 테스트만 사용.
- `tests/voice-input.test.mjs`: 기존 `npm test`와 CI가 음성 단위 시험도 실행하도록 연결.
- `tests/e2e/voice-input.mjs`: 별도 Playwright/설치된 Chrome으로 선택 실행. 합성 음원 사용.

Playwright를 사용할 수 있는 환경에서 개발 서버를 먼저 실행한다. `PLAYWRIGHT_MODULE`에 해당 패키지의 절대 `index.mjs` 경로를 지정하거나, 환경에 설치된 `playwright`를 사용한다. `BASE_URL` 기본값은 `http://localhost:3000`. `node tests/e2e/voice-input.mjs`로 실행한다. 실제 사용자 마이크 대신 임시 합성 WAV를 만들며 종료 후 삭제한다. 프로젝트 의존성을 추가하지 않았다.

### 말한 내용이 글로 나오지 않는 이유

녹음은 실제 MediaRecorder로 수행하지만 `mockTranscribe`는 녹음 내용을 해석하지 않고 언제나 같은 예시 문장을 반환한다. **#14의 W02 개발 단계에서는 의도한 동작**이다. 반면 **#13을 완료하려면 실제 STT 후보로 한국어를 변환하고 역사 용어 결과를 기록해야 한다.** #13의 예시 전사문 허용은 개발을 먼저 진행할 수 있다는 뜻이며 실제 인식 시험을 면제하는 조건은 아니다. W03은 선정한 STT를 서비스 서버·세션·취소·원본 삭제와 연결하는 후속 범위다.

‘말한 문장 대신 고정 예시가 나온다’와 ‘소리가 충분히 들리지 않았다는 오류가 난다’를 구분한다. 후자는 마이크 입력·권한·무음 판정 문제일 수 있으며 mock이라는 이유만으로 정상 처리하지 않는다. 실제 목소리와 기기별 확인이 필요하다.

## 3. 상태와 제한의 의미

`idle → permission → recording → stopping → transcribing → review`, 실패 시 `error`, 취소 시 `idle`.

- 30초에 자동 종료. `timeslice` 횟수가 아니라 단조 증가 시계로 시간을 계산한다. 이벤트 루프 지연으로 30.25초를 넘긴 녹음은 전사하지 않는다. 250ms는 타이머/인코더 종료 오차 허용치이며 서버의 실제 길이 검증을 대신하지 않는다.
- 5 MB는 **5,000,000 bytes**. 청크 누적 중과 마지막 Blob 생성 시 검사. 정확히 한도까지 허용하고 1 byte라도 넘으면 폐기한다. 브라우저가 한 번에 큰 청크를 내보낼 수 있어 순간 메모리 사용량의 절대 상한은 아니다.
- MIME 후보: `audio/webm;codecs=opus`, `audio/mp4`, `audio/ogg;codecs=opus`. `isTypeSupported`로 고르고 실제 recorder MIME을 기록한다. 확장자만 바꾸는 가짜 변환을 하지 않는다.
- 무음은 50ms 간격 RMS ≥ 0.01인 프레임이 3개 이상인지로 판단한다. 음성 의미를 아는 VAD가 아니므로 잡음을 말소리로 오인하거나 작은 목소리를 놓칠 수 있다. 기기별 조정과 W03 서버 검증이 필요하다.
- 권한 요청 자체는 브라우저 API에서 강제 취소할 수 없다. 취소 뒤 늦게 허용된 스트림을 즉시 `track.stop()` 처리하고 이후 녹음하지 않는다.
- 종료 직후 마이크를 해제하고 마지막 `dataavailable`를 합친 뒤 인식 단계로 넘어간다. 녹음기 마지막 이벤트가 없으면 3초 후 오류로 복구한다.
- 취소·초기화·unmount·pagehide·백그라운드 전환 시 자원을 정리한다. 모바일 잠금 중 타이머 지연을 피하려고 숨겨진 페이지의 녹음은 취소한다.
- 녹음 원본은 청크/지역 Blob으로만 처리한다. 파일·localStorage·IndexedDB·객체 URL·서버·로그에 남기지 않는다. 성공/실패/취소 후 참조를 해제하며 브라우저 메모리의 물리적 즉시 소거를 보장한다는 뜻은 아니다. 나중에 실제 adapter를 붙이면 AbortSignal 준수 및 자체 보유 참조 정리가 필요하다.
- UI는 수동 버튼만 전송하며 Enter 자동 전송은 없다. 동기 ref 잠금으로 빠른 중복 클릭을 차단한다. **서버 재전송 멱등성은 아직 구현된 것이 아니다.**

## 4. 선영·민준과 연결할 지점

```tsx
<VoiceInput
  key={sessionId}
  onBeforeRecording={() => stopCurrentSpeech()}
  onConfirm={async (text) => { await sendQuestion(text); }}
/>
```

예시는 연결 형태 설명이며 위 함수들은 현재 구현되어 있지 않다. `onConfirm`은 사용자가 전송한 수정 문자열만 받는다. 실패하면 Promise를 reject해야 입력이 유지된다. 세션 변경 시 key를 바꿔 이전 녹음과 결과를 폐기한다. 부모의 대화 요청 취소/ID 재사용/결과 조회는 부모와 서버가 처리해야 한다. 재생 중단 callback은 새 녹음 직전에 호출된다.

최신 dev의 W01-08 계약(`fa0b5db`, PR #12)에 `docs/API_CONTRACT.md`와 `src/contracts/index.ts`가 추가된 것을 확인했다. `Recording { blob, mimeType, durationMs }`와 `Transcribe(recording, signal)`는 브라우저 기능 내부 인터페이스이며 HTTP 계약을 대체하지 않는다. 공통 파일을 변경하지 않는다.

후속 서버 연결 시 `Recording.blob`을 `TranscriptionRequest.audio`로, 작업 ID를 `requestId`로 전달한다. multipart 필드는 `requestId`와 `audio`이며 Content-Type은 직접 지정하지 않는다. 전사 응답은 `operation: transcription`, `status: completed`인 `CompletedTranscription.text`를 확인·수정란으로 전달한다. `onConfirm(text)`의 문자열은 새 대화 요청의 `TurnRequest.text`로 이어진다. 현재 mock은 기능 내부에서 문자열만 돌려주며 아직 HTTP 요청/응답을 구현한 것은 아니다.

W01-08 리뷰에서 확인할 항목:

1. 계약의 `requestId`+`audio` multipart, 전사 완료 상태와 `text`, 공통 오류 코드를 실제 STT adapter에서 준수하는지 확인.
2. 허용 MIME/실제 코덱, MP4 수용 또는 서버 변환, 5 MB의 byte 정의, 실제 30초 길이 검사.
3. 세션 쿠키/Origin/소유권, 요청 ID 중복과 입력 충돌, 취소 통지와 상태 조회.
4. 성공·실패·취소 시 서버 임시 파일 삭제, 원본 미로깅, 공급자 보존 정책.
5. TTS 정지 및 페이지/세션 초기화 연결, 텍스트 입력 가용성과 전송 진행 상태 공유.

W03에서는 실제 서버 adapter로 교체하고 서버 측 형식·손상·크기·무음 검사, 20초 timeout, requestId/AbortSignal, 공급자 호출과 원본 삭제를 통합한다. 브라우저 MIME 선언과 durationMs는 신뢰할 수 있는 검증 근거가 아니다.

휴대폰에서는 HTTPS 개발 주소가 필요하다. PC의 `http://192.168...` 주소는 보안 컨텍스트가 아니어서 마이크가 차단될 수 있다. iPhone에서는 직접 버튼을 눌러 녹음하고 MP4 MIME, 타임아웃, 잠금 후 마이크 표시 해제를 확인한다. 용량 초과는 자동 시험에서 합성 청크로 재현했으며 실기기에서 우연히 5 MB 파일을 만들 필요는 없다.

W03 이후 추가 시험: 실제 느린 연결/timeout, 취소 직후 서버 결과, 서버 중복 요청/재전송, 실패 입력 보존, 실제 원본 임시 파일 삭제. 현재 코드의 테스트 결과를 해당 서버 보장으로 보고하지 않는다.

## 6. 공유용 짧은 시연 원고

“녹음 시작을 누르면 마이크 권한을 요청합니다. 종료하면 마이크를 해제하고, 이번 주에는 API 없이 예시 인식문을 보여 줍니다. 문장을 고쳐도 자동으로 질문하지 않으며, 전송을 눌렀을 때만 확인한 글이 전달됩니다. 녹음이나 인식을 취소하면 늦은 결과가 나타나지 않습니다. 30초·5 MB 제한과 기본 무음 안내를 구현했고, 실제 휴대폰 호환성과 한국어 STT 정확도는 다음 시험 결과로 구분해 보고하겠습니다.”

이슈는 실기기/STT 시험 및 계약 검토가 남아 있어 임의로 닫거나 완료 표시하지 않았다. GitHub 댓글 게시·push·PR 생성은 수행하지 않았다.
