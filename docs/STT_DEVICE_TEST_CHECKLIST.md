## 간단한 실행 순서

1. “세종대왕은 왜 훈민정음을 만들었나요?”를 녹음하고 종료합니다. 원본 MIME과 인식문을 기록합니다.
2. 전송 전 수신 횟수가 0인지 확인합니다. 글을 수정하고 전송을 두 번 빠르게 눌러 수정 문장이 1회만 전달되는지 봅니다.
3. 취소·다시 녹음·초기화·페이지 이동·잠금/복귀·권한 거절·무음·30초 자동 종료를 각각 시험합니다.
4. 개발 화면의 “전송 실패 시험”으로 수정 문장 보존을 확인합니다. 네트워크를 끊은 STT 실패 후에도 글 입력이 가능한지 확인합니다.
5. `/dev/stt-test`에서 원본과 전송 형식 메타데이터를 기록하고 필요하면 결과 JSON을 내려받습니다.

## 특히 iPhone Safari

원본이 `audio/mp4`/AAC라도 최종 전송은 **WAV/PCM16/16000Hz/mono**여야 합니다. 파일 이름만으로 판정하지 않습니다. Safari 원격 개발자 도구 Network의 `/api/transcriptions` multipart `audio` 데이터를 테스트 음원으로 검사합니다. WAV header의 RIFF/WAVE, format=1, channels=1, sampleRate=16000, bitsPerSample=16을 확인하세요. 서버 Azure adapter도 이 값과 실제 data 길이를 검사하므로, 해당 요청의 `status=completed`까지 확인하면 서버 형식 검증 및 실제 전사 통과의 근거가 됩니다. 단순히 페이지가 표시되거나 목표 형식 안내 문구가 보이는 것만으로 체크하지 않습니다.

원본 음성이나 키는 이슈/저장소에 올리지 않습니다. 결과 기록: 기기·OS·브라우저·원본 MIME·전송 MIME/bytes·인식문·오류·시험일만 남깁니다.
