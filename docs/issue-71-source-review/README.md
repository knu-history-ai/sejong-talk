자동 점검은 로컬 일회성 Python 스크립트로 수행했고, 해시는 평가 브랜치 `core.mjs`의 JavaScript 정규화 방식으로 별도 재계산해 확인했다. 키를 재귀 정렬한 뒤 `JSON.stringify`의 정수 키 열거 순서를 유지한다. 파일 바이트를 그대로 SHA-256한 값과 구분한다. 공식 페이지 사본 해시는 수집한 HTML 바이트의 SHA-256이다. 사이트의 동적 HTML이 바뀌면 같은 URL에서도 사본 해시가 달라질 수 있다.

해시는 저장소 루트에서 아래 명령으로 다시 확인할 수 있다. 기존 평가 도구를 수정하거나 실제 모델을 호출하지 않는다.

```powershell
@'
const fs = require('node:fs');
const { createHash } = require('node:crypto');
const root = 'evals/sejong/date-review-20261015/';
const read = path => JSON.parse(fs.readFileSync(root + path, 'utf8'));
const canonical = value => Array.isArray(value) ? value.map(canonical)
  : value && typeof value === 'object'
    ? Object.fromEntries(Object.keys(value).sort().map(key => [key, canonical(value[key])])) : value;
const hash = value => createHash('sha256').update(JSON.stringify(canonical(value))).digest('hex');
const gold = read('reviewer-only/gold.json');
const expected = read('manifest.json');
const actual = {
  datasetHash: hash(read('model-input/dataset.json')),
  goldHash: hash(gold),
  criteriaHash: hash({ criteriaVersion: gold.criteriaVersion, rubric: gold.rubric, cases: gold.cases }),
};
for (const [key, value] of Object.entries(actual)) {
  console.log(key, value, value === expected[key] ? 'MATCH' : 'MISMATCH');
  if (value !== expected[key]) process.exitCode = 1;
}
'@ | node
```

## 시연님이 진행할 순서

1. 원문 비교표의 공식 링크에서 표제와 국역을 직접 읽고 발췌·생략 문맥을 확인한다.
2. 같은 기사의 문항 비교표에서 **모든 질문 행**을 읽는다. 무엇을 묻는지, 정답의 연·월·일이 맞는지, 본문이 그 답을 뒷받침하는지 확인한다. 본문에 월만 있으면 일자를 만들지 않고, 일자까지 있으면 정답에서 빠뜨리지 않는다.
3. 문항별 사람 판정을 확인 / 수정 필요 / 판단 보류로 남긴다. 수정·보류는 문항 ID와 원문 위치·이유를 함께 적는다. 국역만으로 결정하기 어려우면 보류한다.
4. 아래 기사별 진행표를 갱신한다. 이 표만 체크하고 문항 판정을 생략하지 않는다.
5. 민준에게 수정 의견을 전달하고 수정본을 재확인한다. 검수 가능 여부·실제 검수 날짜도 직접 기록한다.

## 민준의 수정 확인·고정 단계

- 사람 의견을 반영하고 원문·질문·정답 JSON 및 Markdown을 함께 재대조한다. 정답 근거 문자열이 바뀌면 위치와 해시도 함께 갱신한다.
- 미해결 문항은 확정 정답으로 사용하지 않는다. 수정 제안이나 AI 대조만으로 승인 완료로 바꾸지 않는다.
- 개발용/최종 평가용 사건 묶음의 경계와 최종 분량·유형 비율을 결과 열람 전에 정한다. 동일 사건의 관련 기사도 함께 판단한다.
- 수정본 확인이 끝나면 버전·해시·채점 기준을 고정하고 #62에 결과를 공유한다. 이번 문서만으로 #71을 닫지 않는다.
